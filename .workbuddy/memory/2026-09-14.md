### 两个必须记住的技术障碍
- **数学符号编码损坏**：该 PDF 数学字体缺 ToUnicode。`‚`=Θ、`j`=|、`D`=赋值箭头、
  `Œ`=`[`、`W`=`..`、`4`=—（破折号）、`û`=fi 连字、`p`=√、`Š`=阶乘、`<`=`"`、
  数学串里 `.`=`(` `/`=`)`，且减号会被吞掉。**必须靠上下文消歧，不能全局替换。**
  另有一批私用区字形（`\ue001`–`\ue011`、`හ`、`ෂ`）是 ≤/≥/∈ 之类的关系符。
- **插图无法文本还原**（子集化字体导致乱码）。插图要**切图**（原文保真）
  + **SVG 重绘**（交互版）两条腿走。

### 关键技术决策（待用户确认）
- 倾向 **零构建静态站 + 原生 ES Module**：因为要多 agent 并行写文件，
  零构建可避免依赖冲突与构建失败；产出即成品，可直接预览与部署。
- 核心机制：**算法用 JS 生成器（`function*`）写，`yield` 每一步状态**，
  同一份代码既作可运行实现（可断言测试），又驱动逐步动画。
- 关卡模型：**九段式**（位置感 → 直觉 → 原文 → 伪代码 → 动手看见 →
  双轨实现 → 复杂度 → 正确性 → 闯关测验），章末加 Boss 区（原书 Problems）。

## 【重要更正】上面「技术障碍」一节里的符号表有 4 处是**错的**，以下是核实后的版本

上表的 `D`=赋值箭头、`W`=`..`、`E002`=减号/`E003`=加号 全部**与第 4 版原书不符**。
判据：渲染原书页面图像 + 逐条打印命中上下文，未凭推断。正确对应：

| 抽出来 | 真实内容 | 依据 |
|---|---|---|
| `D` | **`=`**（等号，同时用于赋值与判断） | 渲染印刷页 18/19：`for i = 2 to n`、`key = A[i]` |
| `W`（方括号内） | **`:`**（切片，`A[p : q]`） | 第 4 版弃用 3 版的 `A[p .. q]` |
| `U+E003` | **`−`**（减号，全书 3461 次全是减号） | 原脚本把它映射成 `+`，等于把全书减号改错 |
| `U+E002` | **`−`**（93% 是减号；余 7% 是高显示括号，已知残余） | 字形高度分类统计 |
| `U+E011` | **`‖`**（范数，**成对**出现才算一个） | 渲染印刷页 1029 第 33 章势函数证明 |
| 小型大写的连字符 | 前面会多一个空格：`INSERTION -SORT` | 全书 285 处，无「两侧带空格」形式 |

**给后续会话的硬规则**：本 PDF 的符号映射一律以「渲染页面 + 打印上下文」为准，
不要沿用任何未核实的映射表（包括本文件早期版本的）。
