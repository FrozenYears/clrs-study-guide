### 两个必须记住的技术障碍
- **数学符号编码损坏**：该 PDF 数学字体缺 ToUnicode。`‚`=Θ、`j`=|、`D`=赋值箭头、
  `Œ`=`[`、`W`=`..`、`4`=—（破折号）、`û`=fi 连字、`p`=√、`Š`=阶乘、`<`=`"`、
  数学串里 `.`=`(` `/`=`)`，且减号会被吞掉。**必须靠上下文消歧，不能全局替换。**
  另有一批私用区字形（`\ue001`–`\ue011`、`හ`、`ෂ`）是 ≤/≥/∈ 之类的关系符。
- **插图无法文本还原**（子集化字体导致乱码）。插图要**切图**（原文保真）
  + **SVG 重绘**（交互版）两条腿走。

### 关键技术决策（待用户确认）
- 倾向 **零构建静态站 + 原生 ES Module**：因为要多 agent 并行写文件，
  零构建可避免依赖冲突与构建失败；产出即成品，可直接预览与部署。
- 核心机制：**算法用 JS 生成器（`function*`）写，`yield` 每一步状态**，
  同一份代码既作可运行实现（可断言测试），又驱动逐步动画。
- 关卡模型：**九段式**（位置感 → 直觉 → 原文 → 伪代码 → 动手看见 →
  双轨实现 → 复杂度 → 正确性 → 闯关测验），章末加 Boss 区（原书 Problems）。
