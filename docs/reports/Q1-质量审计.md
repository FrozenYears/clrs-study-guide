## 3. 闸门漏报试探（`04_verify_level.py`，原始基线 0 ERROR / 4 WARN）

对金标准关 `site/chapters/ch02-getting-started/s01-insertion-sort.js` 构造 8 个坏变种，逐一改回原状（已用 git/内容比对确认 6 个攻击点全部复原，金标准文件完好）。真实输出见 `_gate_out.txt`：

| B2 页码 17→40 | `page:17`→`page:40` | 2 ERROR / 4 WARN | 🟢 命中（超范围 + 缺 preview 标记） |
| C1 局部换序 | `insertion sort`↔`sort insertion` | **0 ERROR / 4 WARN** | 🔴 **漏报** |
| C2 整句反转 | 整句字符串反转 | **0 ERROR / 4 WARN** | 🔴 **漏报** |

| E 解锁链接改不存在章 | `#/ch02/s02`→`#/ch77/s01` | **0 ERROR / 5 WARN** | 🔴 **漏报**（仅 WARN，未阻断） |
| F viz 改未注册 | `viz:'array'`→`viz:'foo'` | 1 ERROR / 4 WARN | 🟢 命中（引擎白名单校验） |

**根因（内容错误 / 站点故障级风险）：**
- `tools/04_verify_level.py:169` 的 `quote_match` 用**子序列匹配**（`max_run=800` 字符容差），只需“字符按序出现”即可通过，故插入词（A）、局部换序（C1）、整句反转（C2）都仍能凑出子序列 → 漏报。
- `tools/04_verify_level.py:621-625` 对 `/unlocks[…]/url` 指向未建关卡仅 `warn(...)` 而非 `err(...)`，且未区分“章节尚未构建”与“章节根本不存在”；E 把链接改成不存在的 `ch77` 仍只 WARN → **解锁链接缺陷被降级泄露**。
- `shingle_score`（`:156`）定义但未被调用，说明本有更严的连续匹配能力却未启用。

**建议（堵漏，非本次修改）**：① 引述比对改用有序连续匹配或定长 gap（如 `max_run` 降到 ~30），或启用 `shingle_score` 设阈值；② 解锁链接对“章节 id 不在注册表”判 ERROR；③ 对 `preview:true` 的越范围页码保留 WARN，其余越范围页码判 ERROR。
