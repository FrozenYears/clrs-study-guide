## 1. 对 `02_repair.py` 的审计结论

前一位 agent 的脚本思路正确（上下文消歧、不做无脑全局替换），但**有 5 处与第 4 版原书不符的真实错误**。全部以「渲染原页图像 + 逐条打印命中上下文」为判据核实，未凭推断。

### 1.1 `U+E002` / `U+E003` 映射反转（影响全书伪代码）

原脚本：`E002 → −`、`E003 → +`。实测：

- `U+E003` 全书 3461 次，**全部是减号**（`A[1 .. i−1]`、`q − p + 1`）。
  → 原脚本把它变成 `+`，等于**全书伪代码的减号全被改成加号**。
- `U+E002` 1226 次，其中 1149 次（93%）是减号（`n−1`、下标 `a_{n−1}`）。

**修正**：两者都映射为 `−`(U+2212)。保留的唯一歧义记录在 `repair_report.json` 的 `known_ambiguities`。

### 1.2 `D` 被当成赋值箭头 `←`（记法错误）

原脚本按 3 版习惯，把伪代码行里的 ` D ` 换成 `←`。但**第 4 版用普通 `=` 表示赋值**——已直接渲染原书印刷页 18/19 确认：

```
INSERTION-SORT(A, n)
1  for i = 2 to n
2      key = A[i]
```

**修正**：`repair_d_assignment` 改为所有 ` D ` → ` = `，不再区分伪代码/正文。测试断言「全书残留 `←` = 0」。

### 1.3 `W` 被当成区间号 `..`（记法错误）

原脚本把 `AŒ1 W i  1�` 还原为 `A[1 .. i−1]`。**第 4 版改用切片冒号** `A[p : q]`。

**修正**：`BRACKET_SLICE_RE` 在方括号内把 ` W ` → ` : `。测试断言「残留 `..` 切片 = 0」。判据：全书中方括号外的 `W` 一律是普通字母（We / What / Warning）。

### 1.4 `C` → `+` 覆盖面不足且会漏匹配

`C` 是数学字体的 `+` 槽位。原脚本只认「括号内」，导致 `2T(n/2) C Θ(n)`、`j C 1`、`c 1 C c 2` 等大量加号残留（实测 2099 处候选，仅修掉一部分）。

**修正**：`C_PLUS_RE` 扩展为「1–3 字符记号 / 数字 / `)` 与 `(`、`•`、`Θ`、`Ω`、`√`、`⌊` 等数学符号之间的 ` C `」，并配 30 余词英文停用词表兜底。同时修掉两处实现缺陷：双空格 ` C `（数学字体宽度伪影）与字符类未含 `+`。残余从 2099 → 1082，且**没有一处英文误伤**（`a C program`、`Appendix C Counting` 原样保留）。

### 1.5 小型大写的**连字符伪影**

`INSERTION -SORT`、`MAX-HEAP-INCREASE -KEY`、`RANDOMIZED -QUICKSORT` —— 连字符被留在了前一截之后并带一个空格。原脚本只处理了「单字母 + 空格 + 大写串」的拆分，没处理连字符。

**修正**：`SMALLCAPS_HYPHEN_RE = (?<=[A-Z]{3})[ \t]+-[ \t\n]*(?=[A-Z])` → `-`。

判据（实测，非推断）：全书命中 **285 处**，263 处连字符后无空格、22 处后跟换行；**「两侧都带空格」的形式为 0 处**，因此 `A - B` 这类数学减法不会受影响。要求前面至少 3 个大写字母，进一步保证单字母运算安全。修复后残余 0，`INSERTION-SORT` 等名称在全书中以完整形式出现 34/42/29 次。

### 1.6 另外补的两条规则

- **数学函数名跟在空格后**：` .mod p/` → `(mod p)`（`MATH_FUNCS` 白名单）。实测该模式全书的候选词共 63 个，全部是数学记号（单字母变量 / `mod` / `lg` / `degree`），英文散文不会把句点紧贴字母，故放宽安全。
- **范数双竖线**：`U+E011` 全书 76 次，成对出现即一个 `‖`。渲染印刷页 1029 确认是第 33 章势函数证明里的 `‖x^(t) − x*‖²`。修复后 PUA 残余为 **0**。

## 4. 结构化过程的难点与处理方式

### 4.1 页眉页脚

三种形态，全部剔除，且 `test_segment.py` 断言全书 0 残留：

- `<印刷页码> Chapter N <章名>`（如 `36 Chapter 2 Getting Started`）
- `<节标题> <印刷页码>` 形式的节级页眉（如 `2.3 Designing algorithms 39`）
- 孤立页码行、`Problems for Chapter N <页码>`

**并发的坑**：节级页眉会把 `state`（当前处于正文/习题/问题区）误重置，导致「2.1-3」这类跨页溢出的习题掉进 2.2 节。修法是让 `state` 的作用域升到**章**，只在真正的节标题处重置。

### 4.2 伪代码扫描**越界吞行**（本轮发现的最严重缺陷）

前一版扫描器在等待下一个行号时，会把中间所有非编号行一并吞掉。实测：**228 个 run 中 188 个越界，累计吞掉 11393 行正文**（约占全书两成）。

后果：`2.1-3` 到 `2.1-5` 三道习题连同正文整段消失，`p25` 只剩 2 个块。

**修法**：

1. run 的结束位置改为**最后一个带行号的行的下标 +1**，从构造上保证不会跨过正文；
2. 允许的行间空隙上限 2 行，且空隙行必须「像折行尾」——以 `/` `/ /` 注释符、小写单词、`)` `]` `}` 开头；遇到题号 / 节标题 / `Exercises` / `Problems` 一律终止；
3. 折行尾行拼回上一行，不再丢弃。

修后：越界 run **0 个**，折行尾行仅占全书 **0.057%**，正文块从 10190 恢复到 **12284**，习题从 606 恢复到 **759**（与真值一致）。

### 4.3 习题识别与归属

原书把题号**单独排一行**，「2.1-3」与题目正文分处两行；且一节最后几道题常溢出到下一页顶端（那里已经是下一节的地盘）。

**修法**：先把「独立题号」与下一行合并成一段；再按**题号前缀**决定归属（`2.1-3` → 2.1 节），而不是按它在哪一页。这样 2.1 节 5 道题、2.3 节 8 道题全部归位。

### 4.4 跨页断句与断词

- 段落被分页截断时合并回一段；
- 行尾 `-` + 下一行小写 → 词内断行，合回（`run-` + `ning` → `running`）；
- 但 `well-known`、`self-`、`non-` 等真复合词不合（`COMPOUND_PREFIX` 表）。

### 4.5 伪代码名称回退

正常情况：过程名在伪代码上方一行（`MERGE(A;p;q;r)`）。但**代价表重印伪代码时不重复表头**（第 2 章 p.30 的 INSERTION-SORT 代价表）。修法：找不到签名时，向上 8 行内搜「全大写带连字符的名称」；再找不到就**丢弃该 run**——因为列了数字的数据表（排列、示例输入、密文）也会形成编号 run，不设这道闸门会造出大量假伪代码。

## 6. 已知残余与后续建议

1. **组合重音符**（`´ ˛ ˆ ˇ ˚` 共约 1560 处）：抽取时与基字母分离。语义可读，但含帽公式若要精确排版，建议在关卡里直接使用 P2 的切图。
2. **`U+E002` 的少数高括号**（约 77 处，占该字形 7%）：与减号同码位，靠字形高度区分；本轮统一按减号处理，这 77 处会显示为 `−`。已在 `repair_report.json` 记录。
3. **行内 `-` 与数学减号**：原书的连接号（`lines 12–18`）与减号在抽取后同为 `-`/`−` 混用，需要时按上下文判断。
4. **`example` 块仅 1 个**：原书不以 `Example` 起段，属预期，不是漏检。
