## 二、修掉的真错（2 处）

### 1. ch31 的 C 文件头注释写错 Fibonacci 下标

`c/number_theory.c` 与 8 个 ch31 关卡内嵌的同一份代码，头注释都写着：

```
 *   part 2  ...；Fibonacci 最坏情形：gcd(F_20, F_19) 恰好递归 20 次；
```

而代码正文、断言、任务描述、测试表、选择题**全**写的是 `gcd(F_21, F_20)`：

- `c/number_theory.c:149-152`：`ll f21 = fib(21), f20 = fib(20); ... assert(g == 1 && g_euclid_calls == 20);`
- 实测输出：`gcd(F_21, F_20) = gcd(10946, 6765) = 1，递归 20 次 = k ✓`
- 关卡正文：`gcd(F_{21}, F_{20}) = gcd(10946, 6765) = 1` —— 与代码一致。

**这是真错**：`gcd(F_20, F_19) = gcd(6765, 4181)` 的递归步数是 **19** 次，不是 20。头注释里的那一对不能产生它所声称的次数。修法是把 9 份头注释统一成代码实际使用的 `gcd(F_21, F_20)`（`F_21 = 10946`，恰好 20 步）。

涉及 9 个文件：`c/number_theory.c` + `site/chapters/ch31-*/s01…s08`。

### 2. ch32 的 C 文件头注释写错后缀数组倍增轮数

`c/string_match.c` 与 5 个 ch32 关卡内嵌代码，头注释写：

```
 *   part 6  后缀数组："banana" → SA = [5,3,1,0,4,2]，LCP 与暴力一致，倍增 3 轮。
```

而代码断言与实测都是 **2 轮**：

- `c/string_match.c:271`：`assert(rounds == 2);`
- 实测输出：`... LCP 数组 = [1,3,0,0,2]，与暴力逐项一致 ✓`，轮数打印为 **2**。
- 关卡正文明确写「倍增 **2 轮**后 rank 全异（$\lceil\lg 6\rceil = 3$ 的上界之内）」。

数值本身可以手算核对：n = 6，$\lceil\lg 6 \rceil = 3$ 是**上界**，实际 2 轮即区分（第 1 轮 k=1，第 2 轮 k=2 覆盖长度 4，配合已排序的 rank 足以定序）。头注释把上界当成了实测值。涉及 6 个文件：`c/string_match.c` + `site/chapters/ch32-*/s01…s05`。
