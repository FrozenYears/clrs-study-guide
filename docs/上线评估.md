## 一、GitHub Pages：已就绪

**证据（均为实跑结果）：**

1. **全部资源都是相对路径**：`site/index.html` 与 `site/assets/**` 里没有一处以 `/` 开头的引用，
   所以挂在 `https://<user>.github.io/clrs-quest/` 这种**子路径**下也能跑。
2. **子路径实测通过**：把仓库根当 Web 根起服务后访问 `/site/index.html`，返回 **200 / 22,019 字节**。
3. **零构建**：无 npm、无打包器；`site/` 原样上传即可。
4. **零外部请求**：字体走系统字体栈，数学渲染是自研模块，图片全在本地。断网可用。
5. **Jekyll 已关闭**：`site/_dev/` 与 `site/assets/**/__tests__*.mjs` 都是下划线开头，Jekyll 会吞掉；
   已加 `site/.nojekyll`。
6. **发布工作流**：`.github/workflows/pages.yml` —— 先自检（语法 + 12 套行为测试），
   再**排除 `_dev/` 与 `tools/`** 只发布公开面。本地自检不受影响。

**开启步骤：**

```
1. GitHub 建空仓，仓库名建议 clrs-quest（不要勾 README / License，本地已有）
2. git remote add origin git@github.com:<你>/clrs-quest.git
3. git push -u origin master
4. Settings → Pages → Source 选「GitHub Actions」
5. 之后每次 push 到 master 自动发布；也可在 Actions 页手动触发
```

发布后地址形如 `https://<你>.github.io/clrs-quest/`。

## 三、开源前的收尾清单（都很快）

1. **改 Git 身份**（当前是 `WorkBuddy <workbuddy@local>`，不会关联到你的 GitHub 账号）：

   ```bash
   git config user.name "你的名字"
   git config user.email "你的邮箱"
   ```
   注意：**已有提交的身份不会被自动改写**。要让历史提交也归你，需要在第一次推送前改写历史
   （`git filter-repo` 或直接 `git reset --soft` 到首个提交后重做 —— 后者更简单但会丢历史时间线）。

2. **仓库描述与话题**：仓库描述写「CLRS 4th ed. 闯关式交互学习站 · 零构建静态站」；
   topics 建议 `algorithms`、`clrs`、`education`、`static-site`、`vanilla-js`。
3. **README 里的线上地址**：部署成功后把 GitHub Pages 地址加到第一节（现在只有 WorkBuddy host）。
4. **PDF 的历史包袱 —— 已处理**。旧文件名（含 z-library / 1lib / z-lib）原本存在于从首个提交
   到改名之前的每一棵提交树里。已用 `git filter-branch --index-filter` 重写 `master` 的 310 个提交，
   逐提交把该路径改名（blob 内容不动）：

   ```bash
   FILTER_BRANCH_SQUELCH_WARNING=1 git filter-branch -f \
     --index-filter 'sh tools/_rename_pdf_filter.sh' -- master
   ```

   **验证**：`git log --name-only HEAD | grep -i z-library` → 无；重写后 HEAD 的 tree hash
   （`7019e9d0…`）与重写前**完全一致**，证明只改了路径、内容零改动；310 个提交数量不变。

   > **副作用（重要）**：所有提交的 SHA 变了（新 HEAD = `3edd774a`）。`docs/` 与历史报告里
   > 引用的旧 SHA（如 `f2dde5d`、`7529272`）**在 `master` 上已无法解析**。
   > 需要定位某次改动时用 `git log --oneline` 的提交信息检索，不要依赖旧 SHA。
   > 重写用的脚本保留在 `tools/_rename_pdf_filter.sh`（下划线前缀，不进版本库），可供复现。
