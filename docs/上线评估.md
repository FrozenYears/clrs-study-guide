## 一、GitHub Pages：能部署，且已经准备好了

**证据（都是实跑出来的，不是推测）：**

1. **全部资源都是相对路径**。`site/index.html` 与 `site/assets/**` 里没有一处以 `/` 开头的绝对路径，
   所以挂在 `https://<user>.github.io/<repo>/` 这种**子路径**下也能跑。
2. **子路径实测通过**：把仓库根当 Web 根起服务后访问 `/site/index.html`，返回 **200 / 22,019 字节**，
   与直接在 `site/` 起服务一致。
3. **零构建**：无 npm、无打包器、无构建产物；`site/` 目录原样上传即可。
4. **零外部请求**：字体走系统字体栈、数学渲染是自研模块、图片全在本地。断网可用。
5. **Jekyll 已关闭**：`site/_dev/` 与 `site/assets/**/__tests__*.mjs` 都是下划线开头，Jekyll 会吞掉它们；
   已加 `site/.nojekyll`。
6. **发布工作流已写好**：`.github/workflows/pages.yml` —— 先自检（语法 + 12 套测试），
   再**排除 `_dev/` 与 `tools/`** 只发布公开面。

**开启步骤：**

```
1. GitHub 建空仓（不要勾 README/License，本地已有）
2. git remote add origin git@github.com:<你>/<repo>.git
3. git push -u origin master
4. 仓库 Settings → Pages → Source 选「GitHub Actions」
5. 之后每次 push 到 master 自动发布；也可在 Actions 页手动触发
```

## 二、原样公开的两个硬阻塞

### 阻塞 1：版权（决定性，不是技术问题）

| 材料 | 位置 | 规模 |
|---|---|---|
| CLRS 第 4 版 PDF | 仓库根目录 `.pdf` | 11.47 MB |
| 逐字英文引述 | `site/chapters/**` 的 `en` 字段 | 站点统计 1,882 条 |
| 原书插图 | `site/figs/`（108 张）、`data/figs/`（256 个 PNG） | 200 DPI 书页裁切 |
| 原书习题题干 | `site/assets/data/problems.js` 与各关卡 | 599 道 |
| 抽取语料 | `data/pages*.jsonl`、`data/blocks/` | 5.6 MB 书页文本 |

这些材料的著作权属于 Pearson 与作者。**任何开源许可证都无法覆盖它们** —— `LICENSE` 里的 MIT
只能授权本项目的代码（这一点已写进 `LICENSE` 的 Scope note 与 `README` 第六节）。

公开可索引的 GitHub 与「自己搭个站」性质不同：会进搜索引擎与代码搜索索引，
收到 DMCA 通知的概率显著高于现在的私有托管。

> 引用、评论在多数法域有合理使用/引用例外，但**整套逐字复刻**通常超出该例外。

### 阻塞 2：PDF 已经进了 git 历史，删文件删不干净

`git log -- '*.pdf'` 只有 1 个提交，但那次的 blob（`b15152a3`，**11,473,766 字节**）
永久留在历史里。现在 `git rm` 只是从最新提交移除，clone 的人照样拿得到。
当前 pack 共 30.4 MiB，其中约 11 MB 就是这个 PDF。

要真正移除，需要重写历史：

```bash
# 需要先装 git-filter-repo（或用 BFG）
git filter-repo --path-glob '*.pdf' --invert-paths
git push --force --all      # 强推；协作者需重新 clone
```

### 次要项

- **Git 身份**：当前提交者是 `WorkBuddy <workbuddy@local>`，不会关联到你的 GitHub 账号。
  公开前建议 `git config user.name "你的名字"` / `git config user.email "你的邮箱"`；
  **已有历史提交的身份不会被自动改写**。
- **仓库体积**：855 个追踪文件、30.4 MiB pack、`data/` 占 29 MB。公开仓不建议带整个语料。
- **AI 生成内容**：中文讲解是模型产出。部分法域下纯 AI 生成内容不受著作权保护，
  所以 `LICENSE` 说的是「代码」而不是「全部内容」，这是准确口径。
- **第三方代码**：站点**没有**打包任何第三方库（KaTeX 未 vendor，`core/katex.js` 是自研轻量渲染器），
  因此不存在许可证兼容问题。Python 工具链的依赖只在你本地跑，不随站点分发。
- **无 service worker**：首次访问仍需网络，第二次靠浏览器缓存。对外**不要**宣传成「完整 PWA 离线」。

## 三、要公开，三条路

### 方案 A（推荐）：公开仓只放代码，内容留在本地

- **公开**：`site/assets/**`（运行时）、`tools/**`（语料流水线与检查工具）、`c/*.c`、`docs/**`（方法论文档）。
- **不公开**：PDF、`data/pages*.jsonl`、`data/blocks/`、`data/figs/`、`site/figs/`，
  以及关卡里逐字引用的 `en` 字段与习题原文。
- **代价（必须先想清楚）**：关卡的英文引述与中文讲解现在**写在同一个文件里**
  （`site/chapters/**/s*.js` 的 `en` / `zh` 字段混排）。要剥离，得给 `tools/dump_levels.mjs`
  加一步「导出脱敏关卡」：产出只有中文讲解、把 `en` 替换成「见原书 p.XX」的关卡集，
  并让站点支持这种降级形态。**这是一次真实改造，不是改个配置。**
- **好处**：公开后无版权风险；语料流水线 + 溯源检查工具本身就是有复用价值的技术示范。

### 方案 B：公开整仓，接受风险

也就是之前对 WorkBuddy host 的选择，但 GitHub 暴露面更大。若走这条，最低限度：

1. 把 PDF 移出仓库并**重写历史**抹掉（见上）；
2. 改流水线：`tools/01_extract.py`、`tools/04_figures.py`、`tools/11_align_printed.py`
   现在硬编码从仓库根读 PDF，必须先改成读外部路径；
3. README 里保留 `LICENSE` 的范围说明与风险提示（已有）；
4. 仓库描述写明「非官方，与作者/出版社无关」。

### 方案 C：只发布站点，仓库保持私有

GitHub Pages 对**私有仓**需要付费计划（Team/Enterprise）；免费账号只能从 public 仓发布。
或者把 `site/` 产物推到另一个内容仓 —— 但版权问题不因此消失，只是换个地方。

## 四、推荐路径

1. **先决定 A 还是 B。** 这一步只有你能定，取决于你愿意承担多少法务风险；
   agent 不替你选。
2. 走 A：先做「导出脱敏关卡」工具，再建公开仓。
3. 走 B：先 `git filter-repo` 抹 PDF + 改流水线读外部路径，再建仓。
4. 无论哪条：改 `git config user.email`；推上去后确认 Actions 里的自检与部署都绿。
5. 部署完成后，把 README 里的线上地址从 WorkBuddy host 换成（或并列加上）GitHub Pages 地址。
