# 关卡编写手册

给「接下来要写某章某一关」的人（不管是人还是 agent）。目标：**照做就能交付一关过关的关卡**，
而且不需要重新发现我们已经踩过的那十几个坑。

配套文档：
- `docs/开发规范.md` —— 数据契约（九段式 schema、令牌、帧契约）与红线，写代码时查它
- `docs/建设计划.md` —— 整体架构与分期计划

## 一、四步流程

```bash
# 0) 先把引述挑好（最关键的一步：检查对引述没有相似度阈值）
python tools/07_pick_quotes.py pick 3 3.1           # 列出本节所有能通过检查的引述候选
python tools/07_pick_quotes.py pick 3 3.1 --fail    # 只看通不过的，便于排查
python tools/07_pick_quotes.py check my_quotes.json # 自己拼/改过的引述，逐条预检
python tools/07_pick_quotes.py show 3 3.1 7 8 12    # 按块下标看完整正文（块是句子碎片时用）

# 1) 生成骨架（引述 / 伪代码 / 书后习题会自动从语料里逐字填好）
python tools/05_new_level.py 3 3.1 --register

# 2) 填掉文件里所有 【TODO …】
#    这一关的讲解、直觉、动画配置、C 代码、测验题都在这一步写

# 3) 跑检查，直到 0 ERROR、0 TODO
node tools/dump_levels.mjs
python tools/04_verify_level.py
```

> ★ **为什么第 0 步要放在最前面**：手写引述最容易出的是「差一两个字符」的错
> （漏一个词、把语料伪影顺手"修正"、页码差一页），而检查**没有相似度阈值**，
> 只会报「溯源失败」。若等写进文件再跑检查，就陷入「改一次、跑一遍」的循环。
> `07_pick_quotes.py` 复用检查自己的 `verify_quote`（**不是**第二套判据 ——
> 项目曾因两套归一化并存而白跑一轮，见第四节坑 16），把判据前移到你挑引述的那一刻。
>
> 该工具带自检：`python tools/07_pick_quotes.py selftest`。它同时把检查的
> **已知边界**（删 1–2 个字符的篡改仍会通过，见 `docs/reports/Q1-质量审计.md`）
> 写成了可执行记录 —— 边界应当被记进代码，而不是靠人记得。

再顺手跑一次站点自检（第 2 步改的是站点文件）：

```bash
node site/tools/check-syntax.mjs .        # 语法
python tools/smoke_browser.py 8317        # 逐路由真实渲染（需先起本地服务）
```

> ★ 新关卡**必须同时进 `tools/smoke_browser.py` 的 `CASES`**，否则等于没做渲染验证。
> 全量扫描要十几分钟，所以写单关时可以只跑自己那几条路由（临时把 CASES 换成自己的），
> **但每章收口时一定要跑一次全量** —— 第 6 章收口时正是全量扫描抓出一条过期期望
> （计数器标签改名后，`smoke_browser.py` 里还留着旧字符串）。

本地服务：`cd site && python -m http.server 8317 --bind 127.0.0.1`

## 二、生成器帮你做了什么

`tools/05_new_level.py <章号> <节号>` 从 `data/blocks/` 取数，把**四类必须逐字照抄的内容**
填进骨架，并**当场用检查的判据自检**——通不过的候选不会写进文件，而是打印出来说明原因：

| 内容 | 来源 | 为什么不能手抄 |
|---|---|---|
| 原文引述（`en` + `page`） | `data/blocks/…json` 的 `body` / `figure-caption` | 凭记忆写必然出错（Figure 2.4 的数组就写错过） |
| 伪代码逐行（`n` + `code`） | 同上的 `pseudocode` 块 | 行数、标点、注释都是考点 |
| 书后习题（`id` + `statement` + `page`） | 同上的 `exercise` / `problem` 块 | 题号与题干错位很难发现 |
| 页码锚点、前置/解锁链接 | `data/structure.json` | 写错页码 = 误导读者（检查会拦） |

参数：`--slug`（文件名后缀）、`--title-zh`（中文标题）、`--chapter-title-zh`（新建 chapter.js 用）、
`--register`（写进章节注册表）、`--dry-run`（只打印不落盘）。

## 三、九段式每一段要写什么

顺序固定，类型与字段见 `docs/开发规范.md` 4.2。下面只讲**每段的验收标准**。

| # | 阶段 | 交付标准 |
|---|---|---|
| 1 | `map` 位置感 | 说清「为什么学这一关」与「它在知识地图上的位置」；`unlocks` 指向真实的后续关卡 |
| 2 | `intuition` 直觉 | 一个具体场景 + 2–4 段中文，把场景接到本节内容；**原书没有类比时要自己造一个** |
| 3 | `source` 原文 | 每条 `en` 逐字来自语料、`page` 正确；每条配 `zh` 中文解读；术语卡给 `page` |
| 4 | `pseudocode` | 行号与原文一致；给需要解释的行补 `zh`（不补则该行不可点） |
| 5 | `visualize` | `viz` / `algorithm` 必须是已注册的（`site/assets/viz/`、`site/assets/algorithms/`）；`presets` 至少包含原书图里那组数组；`invariants` 要能在动画里判定真假 |
| 6 | `code` | 内嵌 `c.code` 与 `c/*.c` **逐字节一致**；`mapping` 给出「伪代码行 ↔ C 行」对应 |
| 7 | `analyze` | 每条复杂度断言都要 `page`；**自己推导的写 `source: 'instructor'`**；引用本关范围之外的页码必须加 `preview: true` |
| 8 | `prove` | `statement` 也要逐字取自原书；三步分别对应不变量的 Initialization / Maintenance / Termination |
| 9 | `drill` | 6–8 道自测题（`judge` / `single` / `simulate`）；`bookExercises` 已由生成器填好，你只需补 `hint` |

## 四、坑清单（全部真实踩过）

### 内容正确性

1. **英文引述不要凭记忆写。** 语料里有，就去 `data/blocks/*.json` 里取。检查按「引述的字一个
   不缺、按原序出现在声明页 ±1 窗口里」判定，**没有相似度阈值**——放过一次就等于允许改写原文。
2. **不要给自算的结论安上「原书给出」。** Σtᵢ = 14 是我们自己算的，原书 p28–34 没有这个数；
   写成「正文表格给出」就是杜撰归属。自算的标 `source: 'instructor'`。
3. **注意记法版本。** 第 4 版：赋值用 `=`、切片用 `A[p : q]`。写成第 3 版的 `←` / `A[p .. q]` 是错的
   （C 代码里的 0 基 `..` 是 C 侧自己的约定，关卡里要写明对应关系）。
4. **页码越界必须标 `preview: true`**（比如在 2.1 关引用 2.2 节的结论），否则读者以为结论来自本节。
5. **术语卡是词表，不是句子。** 给 `en` / `zh` / `page` 即可；检查只要求每个英文词能在声明页附近找到。

### 技术约束

6. **`chapter` 写数字字面量**（`chapter: 3`），不要写字符串 `'3'`——检查按它推 `id = 'ch03/s01'`。
7. **`chapter.js` 只 import 已经建好的关卡文件。** 它被 `site/assets/chapters.js` 静态 import，
   import 一个不存在的文件会让**整个站点**加载失败。
8. **JS 注释是 `//`**，不是 `#`（生成器第一版就是拿 `#` 生成注释，产出直接是语法错误）。
9. **`【TODO …】` 是给检查看的占位标记**，会单独统计；写完记得清空。
10. **`**粗体**`、`$公式$`、`` `代码` `` 在文案里都能用**——`renderMixed` 支持（前提是写在会被
    渲染的字段里；`en` 原文里不要出现 `**`，检查会报错）。
11. **LaTeX 命令必须已被渲染器实现。** 站内有静态扫描（`__tests-katex__.mjs` 第 [11] 段）会列出
    关卡里用到但没实现的命令——新引入命令时先补实现，否则页面上会出现 `\textfor` 这种碎片。
12. **表格单元格走 `renderMixed`**，所以公式与粗体都能用；纯代码别塞进表格（等宽显示会误导）。

### 工具链

13. **改 PDF 解析规则后要按顺序重跑**：`02_repair.py` → `test_repair.py` → `03_segment.py` →
    `test_segment.py` → `dump_levels.mjs` → `04_verify_level.py`。
14. **审计/自证规则时必须在 `data/pages.jsonl`（未修复原文）上做**：修复后的文本里伪影已消失，
    拿它当依据会得出完全错误的结论（踩过）。
15. **页眉剥离正则必须形状严格，且全项目只有一套**（`03_segment.py` 的 `RUNHEAD_RES`）。
    宽松版会把正文整句删掉，而现场看不出原因。
16. **引述比对只有一个入口且必须用 `qnorm`**（去空白、去连字符、下标折数字、省略号折点）。
    曾并存两套归一化，术语卡走了弱的那套，于是永远匹配不上。

### 站点渲染（第 5、6 章新增）

17. **纯文本渲染的字段不能放 LaTeX。** `stage.title` 与 `pseudocode.more[].subtitle`
    走的是 `h('h3', {}, '…' + sub)`，**没有** renderMixed —— 放了 `$\Theta(1)$`
    页面就原样显示反斜杠，而且**不报错、不白屏**。
    可以放 LaTeX 的是：`zh` / `body` / `note` / `lead` / `intro` / 表格单元格 /
    `claims[].when` / `mathKit[].title` / `derivations[].steps[].zh`。
    **新增字段前先确认它走不走 renderMixed**（在 `ui/stages.js` 里搜该字段名）。
    自查脚本：
    ```bash
    python - <<'PY'
    import re, os
    for ch in sorted(os.listdir('site/chapters')):
        d = os.path.join('site/chapters', ch)
        if not os.path.isdir(d): continue
        for f in sorted(os.listdir(d)):
            if not f.endswith('.js'): continue
            t = open(os.path.join(d, f), encoding='utf-8').read()
            for m in re.finditer(r"type: '[a-z]+', title: '([^']*)", t):
                if '$' in m.group(1): print('STAGE ', f, m.group(1)[:60])
            for m in re.finditer(r"subtitle: '([^']*)", t):
                if '$' in m.group(1): print('SUBTL ', f, m.group(1)[:60])
    PY
    ```
18. **检查会把「被 import 的关卡有语法错」报成 `chapter.js 加载失败`。**
    看到这条 ERROR 要**顺着 import 链**去找真正的坏文件，别盯着 `chapter.js` 看 ——
    它只是链条断开的地方。
    最容易触发的一类写法：在单引号字符串里写 `BUILD-MAX-HEAP$\'$` ——
    `\'` 会提前结束字符串。撇号请用 Unicode `′`（`U+2032`）。

### 自检与实验（第 5、6 章新增）

19. **要拿去支撑结论的统计量，实验里必须先 `printf` 出原始数字。**
    教训：`INCREASE-KEY` / `INSERT` 的上浮循环漏写了比较计数，"反复插入建堆"实验的
    比较次数恒为 **0**，而**没有任何断言覆盖这个量** —— 是打印出来的那一行数字暴露的。
    结论：断言只覆盖你想到的情形；原始数字会暴露你没想到的。
20. **先测量，再写断言。** 别凭直觉写不等式。教训：关于「反复插入 vs 自底向上建堆」
    比较次数的两条断言实测**都不成立**（递增输入下自底向上也很费劲，两者接近）。
    正确顺序是：先 `printf` → 看清数字 → 挑出真正成立且**确定性**（种子固定）的几条
    写成断言。
21. **概率类自检要用卡方，不要拍「偏差 < x%」。** 后者与样本量挂钩：N 大时抽样噪声
    本身就超过阈值，必然假失败。判据写「χ² < 3×自由度」，因为这个统计量的期望恰好
    等于自由度，与 N 无关。另外 PRNG 用「线性同余 + 取模」会把洗牌洗歪
    （低位周期为 2，n=4 时偏差 17%）；即使换 xorshift32，**连续种子**仍因线性映射
    而相关（偏 9%）—— 种子必须先做一次乘法混合。

22. **文案里写 `Figure X.Y`，段尾就会挂出原书那张切图**（`ui/figures.js` +
    `tools/12_publish_figs.py`）。约定三条：
    ① 图号必须是原书真实存在的编号（`data/figures.json` 里切过图的那些），
      写了没切图的编号，页面上不会出错、但也不会有图；
    ② 同一段里一张图只出现一次，顺序按它第一次被提到的先后 —— 所以不必在数据里
      另加 `figure:` 字段，文本本身就是依据；
    ③ 引用一串图时只有第一个带前缀是允许的（`Figures 13.5 and 13.6`），
      识别规则与发布脚本必须一致（改一处要改两处）。
    新增/更换图后重跑：`node tools/dump_levels.mjs && python tools/12_publish_figs.py`，
    再 `node site/assets/ui/__tests-figures__.mjs` 验清单与文件一一对应。

## 四·五、并行子代理的指令模板（第 5 章定稿）

一章的关卡可以并行写，但**公共文件必须由协调者收口**。下面是踩过坑后定下的分工。

### 每个子代理负责什么

- **只写自己那一关**：`site/chapters/<章目录>/s<NN>-<slug>.js` 与配套的 `c/<name>.c`。
- **不许改**：`chapter.js`、`site/assets/chapters.js`、`site/index.html`、
  `site/assets/ui/**`、`site/assets/algorithms/**`、别人的关卡文件。
  这些由协调者统一收口（并行改会互相覆盖）。

### ★ 必须允许它做的一件事

**允许子代理在自己的关卡建好后，临时把 import 与 `levels` 项加进 `chapter.js`，以便跑检查。**

原因：`tools/dump_levels.mjs` 是逐章 `import chapter.js` 再取 `ch.levels` ——
**没登记进 `levels` 的关卡文件根本不会被检查**，跑出来的「0 ERROR」是假的。
第 5 章吃过这个亏：当时给子代理的指令是「不许碰 chapter.js」，于是它们的自我验收
全部空转（其中一个自己发现了，还贴心地在文件里写了「临时注册」注释）。
协调者收口时会把 `chapter.js` 整体重写成最终版本，所以临时改动不会留痕。

### 指令里必须写清的四件事

1. **语料块范围**：告诉它 `data/blocks/<file>.json` 里 `section == 'x.y'` 的**节内下标区间**
   （含习题所在的那几块）。否则它得自己摸索。
2. **挑引述的配方**：明确要求用 `tools/07_pick_quotes.py pick/check`，
   并强调**不许凭记忆写英文**、`en` 里不许出现 `**`（检查会报 ERROR）。
3. **生成器与行号约定**：如果这一关要驱动动画，把生成器的**行号含义**原样抄给它
   （教学伪代码的行号必须与生成器逐行对上）。
4. **数值/实验的要求**：C 程序要能 `-Wall -Wextra -Werror` 零警告、断言自证；
   并要求它**把关键数字打印出来**（见坑 19）。

### 协调者收口清单

1. 以**磁盘文件**为准逐关验收 —— 子代理可能死于限流（429）而**没有报告**，
   但文件已经写完。既不要把「没报告」当成「没干活」，也不要把代理的汇报当成验收结果。
2. 重写 `chapter.js`（正式登记全部关卡）、必要时更新 `index.html` 的 `count`。
3. 把新关卡的路由加进 `tools/smoke_browser.py` 的 `CASES`。
4. 跑检查 + 语法 + 逐路由，然后提交。
5. 检查风格一致性 —— 第 5 章有一个子代理整篇用了双引号（497 处），
   与站内单引号风格不一致。**没有盲目批量替换**（内嵌的 C 代码里有大量双引号，
   盲改会破坏检查的逐字节比对），而是记录下来留待专门处理。

## 五、环境备忘

- **Git Bash 的 PATH 是坏的**：`ls` / `mkdir` / `rm` / `head` / `tail` / `dirname` 全部 command not found。
  文件操作请用 PowerShell，或直接用 Python 绝对路径执行脚本。
- Python：`python`
- Node：`node`
- C 编译器：`C:\msys64\ucrt64\bin\gcc.exe`（用 `-std=c99 -Wall -Wextra -Werror` 验证）
- 想看渲染效果：无头 Chrome dump DOM 或截图，再用 pymupdf 裁剪放大肉眼核对。
