| 抽取结果 | 真实内容 | 说明 |
|---|---|---|
| `‚.n 2 /` | `Θ(n²)` | `‚`=Θ，`.`=`(`，`/`=`)` |
| `O.n lg n/` | `O(n lg n)` | 同上 |
| `jEj <3  jV j` | `\|E\| ≤ 3\|V\|` | `j`=`\|` |
| `AŒ1 W i  1�` | `A[1 .. i − 1]` | `Œ`=`[`，`W`=`..`，`−` 被吞掉 |
| `key D AŒi�` | `key = A[i]` | `D`=赋值箭头 `←` |
| `engineering4such` | `engineering—such` | `4`=破折号 |
| `ûnd` / `ûn` | `find` / `fin` | fi 连字 |
| `p n` / `nŠ` | `√n` / `n!` | `p`=根号，`Š`=阶乘 |
| `<coded=` | `"coded"` | `<`=`"`，`=`=`"` |

**应对**：流水线第 2 步建立**符号修复表**（按"上下文 + 相邻字符"消歧，而非无脑全局替换），并用抽样的原始页码做回归验证。修复脚本与映射表一并入库，任何一条规则都可追溯到验证样本。

**障碍 2：插图（Figure）无法用文本方式还原。** 图 2.1 抽出来是 `♥ ♥ 2 ♥ 4 ♥ ♥ ♥` 这样的乱码——说明图中文字使用了子集化字体。本书的图（排序过程图、红黑树旋转、B 树分裂、流网络、FFT 蝶形图等）恰恰是理解算法的关键。

**应对**：插图分两条腿走：
1. **切图**：用高 DPI 把原文插图区域裁成 PNG，作为"原文插图"原样呈现（保证忠实）；
2. **重绘**：对需要交互的图，用 SVG 重绘为**可动、可点、可输入**的版本（这是本站的核心价值所在）。
两者并排放置，用户随时可对照"书上原图"与"可操作版"。

## 1. 产品定位

一句话：**把 CLRS 从"论文体的教科书"翻译成"可以动手的关卡地图"。**

三条设计原则：

1. **忠实优先（Fidelity first）** — 每一个关卡都声明它对应原文的哪一页；每条结论都要能在原文找到出处；伪代码逐行对齐原书。
2. **零基础起步（No prerequisites）** — 书里默认你会 ∑、会概率、会图论术语。本站把这些**在用到的那一关里就地补上**（"数学急救包"），不让新手卡在附录上。
3. **一份代码两种用途（One code, two uses）** — 算法用 JS 生成器（`function*`）写，`yield` 每一步状态。于是**同一份代码**既能作为"可运行实现"（可以断言测试），又能驱动"逐步动画"。避免"教学伪代码"与"真实实现"两张皮。

## 2. 关卡模型：九段式

每个**节（Section）= 一关**；每关固定拆成 9 个阶段，从"看见"到"会证"逐级递进。这是本站的骨架，全书 149 关共用同一套节奏——学生一旦熟悉，学习成本就转移到内容本身。

| # | 阶段 | 中文名 | 交互形态 | 解决什么问题 |
|---|---|---|---|---|
| 0 | Map | **位置感** | 全局进度星图 + 前置依赖箭头 | 我在哪？为什么要先学它？ |
| 1 | Intuition | **直觉入口** | 生活化场景（扑克牌/排队/找路）+ 拖拽小游戏 | 先有画面，再上数学 |
| 2 | Source | **原文精读** | 英文原文段落 + 逐句中文注解 + 术语卡悬停 | 严格贴原文 |
| 3 | Pseudocode | **伪代码骨架** | 逐行高亮、点击展开解释、变量追踪表 | 从自然语言到形式化 |
| 4 | Visualize | **动手看见** | 步进器：播放/暂停/单步/回退/调速/自定义输入 + **不变量实时显示** | 看见算法真的在跑 |
| 5 | Code | **双轨实现** | 伪代码 ⟷ 可编辑可运行的 JS ⟷ C 版本对照（含断言测试） | 严谨、可验证 |
| 6 | Analyze | **复杂度** | 递归树/求和/渐进记号**交互推导** + 曲线对比图 | 会算，不是背 |
| 7 | Prove | **正确性** | 不变量/归纳法分步展开，每步可折叠 | 知其所以然 |
| 8 | Drill | **闯关测验** | 判断/选择/伪代码填空/手动模拟/原书习题（带提示） | 检验掌握 |

**章末 = Boss 区**：精选原书章末 Problems（如 2-1、4-6、15-3 这类带 ★ 的难题），只给提示不给答案，做完解锁"通关徽章"。

**规模估算**：149 关 × 9 阶段 ≈ **1300+ 个可交互单元**。这是一座真正的大型站，必须分期交付（见第 8 节）。

## 5. 技术架构

### 5.1 技术栈建议：零构建静态站

**推荐：原生 ES Module + 自研微型运行时（< 5KB），无 npm、无打包步骤。**

理由（针对本项目特殊性）：
- 站点由**多个并行 agent 同时写文件**产出。零构建意味着**没有依赖版本冲突、没有 npm install 竞争、没有构建失败阻塞**，每个 agent 只碰自己那一章的文件。
- 产出即成品：`site/` 目录直接就能打开预览，也能原样部署到任何静态托管。
- 不会被框架升级/工具链腐化——这是个要长期维护的学习站。
- 需要的全部能力（路由、状态、DOM 渲染、SVG 动画）用原生三件套都做得到，且性能更好。

数学公式用 **离线内置的 KaTeX**（本地 vendor 一份，保证断网可用）。

### 5.4 核心机制：一条代码，两种用途

```js
// 算法本体：既是可运行实现，也是动画数据源
export function* insertionSort(A) {
  for (let i = 1; i < A.length; i++) {
    const key = A[i];
    let j = i - 1;
    yield { line: 1, hi: [0, i], note: 'A[0..i-1] 已排序（循环不变量）' };
    while (j >= 0 && A[j] > key) {
      A[j + 1] = A[j];
      j--;
      yield { line: 5, hi: [j + 1, i], cmp: [j, j + 1] };
    }
    A[j + 1] = key;
    yield { line: 8, hi: [0, i] };
  }
}
```

- **当作实现用**：跑完全部 yield，断言结果正确 → 单元测试通过；
- **当作动画用**：`stepper.js` 把每个 yield 映射成帧，实现单步/回退/调速。

这样"教学用的伪代码"和"真实跑的实现"永远同步，也满足"代码严谨"。

## 9. 质量保证：怎么证明"严格尊重原文"

1. **页码锚点强制**：每关的内容文件必须声明 `source.printed`，审计脚本检查区间是否覆盖了该节全部原文页。
2. **伪代码逐行对齐**：从语料里抽出原书伪代码 → 规范化 → 与站点伪代码做行级 diff，行数/关键字/顺序不一致就报警。
3. **结论溯源**：站内出现的每一个 `Θ/Ο/Ω` 复杂度断言，都要能匹配到原文的对应表达式；匹配不到的一律标为"讲师补充"并显式标注。
4. **术语一致性**：站内术语表从原书 Index（印刷页 1250–1290）反向生成，保证中英对照不跑偏。
5. **补充内容必须标记**：凡是"我的理解/类比/额外例子"，UI 上统一用不同底色标注「讲解补充」，与「原文」在视觉上严格区分。
