# 开发规范（所有 Agent 必须遵守）

本文件是**契约**。任何内容 Agent、可视化 Agent、实现 Agent 在动手前必须先读完本文件。
违反本文件任何一条「红线」的产出，一律打回重做。

## 一、红线（不可违反）

| # | 红线 | 判定方式 |
|---|---|---|
| R1 | **每个内容文件必须声明 `source` 页码锚点**，且区间必须覆盖该节对应的原文印刷页 | 审计脚本检查 |
| R2 | **不得杜撰结论**。任何复杂度断言（Θ/Ο/Ω）都必须来自原文，并在 `page` 字段标出出处；若是你推导补充的，必须标 `source:'instructor'` | 审计脚本 + 人工复核 |
| R3 | **原文与讲解必须视觉可分**。原文段落用 `data-kind="source"`，讲解补充用 `data-kind="note"`，两者样式不同，不得混排 | 目视 + DOM 检查 |
| R4 | **术语必须中英对照**，英文取自原书原文，不得自创译名 | 术语表比对 |
| R5 | **CSS 只能使用 `assets/theme.css` 定义的设计令牌**，禁止硬编码颜色/字号/圆角 | grep 检查 `#hex` 与 `px` 字号 |
| R6 | **禁止引入任何 npm 依赖或网络资源**。数学公式用本地 `assets/vendor/`，字体用系统字体栈 | grep 检查 `<script src=http`、`@import url(http` |
| R7 | **每个交互组件必须支持键盘操作**，且尊重 `prefers-reduced-motion` | 手工测试 |
| R8 | **不得修改不属于自己的文件**（见第二节的文件归属） | 目录约定 |

### 4.3 动画帧契约（可视化引擎与算法实现的接口）

算法实现写成 JS 生成器，**每个 `yield` 就是一帧**：

```js
// site/assets/algorithms/insertion-sort.js
export function* insertionSort(A) {
  for (let i = 1; i < A.length; i++) {
    const key = A[i];
    let j = i - 1;
    yield { line: 1, highlight: { active: [i], sortedPrefix: i }, note: 'A[1..i-1] 已排序' };
    while (j >= 0 && A[j] > key) {
      yield { line: 5, highlight: { compare: [j, j + 1] }, counts: { cmp: 1 } };
      A[j + 1] = A[j];
      j--;
      yield { line: 6, highlight: { move: [j + 1] } };
    }
    A[j + 1] = key;
    yield { line: 8, highlight: { active: [j + 1] } };
  }
  yield { line: null, done: true, array: A.slice() };
}
```

标准帧字段（**所有算法必须用这套字段名**）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `line` | int\|null | 当前执行的伪代码行号，用于侧栏高亮 |
| `array` | number[] | 数组全量快照（小 n 用快照，大 n 用 delta） |
| `pointers` | object | `{ i: 3, j: 1 }` 指针位置 |
| `highlight` | object | 见下 |
| `note` | string | 这一帧的一句话中文解释 |
| `counts` | object | `{ cmp: 1, swap: 1 }` 累加计数 |
| `invariantHolds` | boolean | 当前不变量是否成立（用于阶段 4 实时显示） |
| `done` | boolean | 是否结束 |

`highlight` 的标准键（语义固定，颜色由 theme.css 决定）：

`compare` 比较中 · `active` 当前操作 · `move` 正在移动 · `sortedPrefix` 已确定前缀
· `pivot` 轴 · `visited` 已访问 · `frontier` 待处理 · `path` 结果路径 · `violation` 违反不变量

## 五、代码轨道规范

**站内展示的代码只有两轨：原书伪代码 + C 实现。** 驱动动画的 JS 实现在页面中默认**折叠隐藏**，仅提供「查看驱动动画的实现」入口（满足好奇，不干扰主线）。

### 5.1 伪代码

- **必须与原文逐行一致**：行号、顺序、关键字（`for`/`while`/`if`/`return`/`and`/`or`）全部照抄。
- 保留原书的排版惯例：赋值用 `=`，数组下标用 `A[i]`，区间用 `A[1 .. i-1]`。
- 中文注释放在右侧独立列，不插进代码里。

### 5.2 C 实现

- C99 标准；**面向"有 C 基础的学生"**，不用晦涩技巧。
- 风格：`snake_case` 函数名、4 空格缩进、大括号独占一行。
- 数组一律带长度参数（与伪代码的 `n` 对应）；**下标从 0 开始**，但页面上必须显式说明
  「书中伪代码从 1 开始，C 从 0 开始，因此 `A[i-1]` 对应书中的 `A[i]`」——这是新手最容易翻车的点。
- 每个算法配一个可编译的 `main` 与断言，放在 `c/<name>.c`，用 `assert` 校验。
- 必须能通过 `gcc -std=c99 -Wall -Wextra` 零警告。

### 5.3 三者对应关系

页面上必须有一张「伪代码行 ↔ C 行」对应表，让学生知道每一句落在了哪里。

## 六、文案规范（中文讲解 + 英文术语）

1. **语体**：第二人称直述，「你现在手里有一个长度为 n 的数组」。不用「我们」堆砌，不用「众所周知」。
2. **术语**：首次出现写「中文（English）」，例如「循环不变量（loop invariant）」；之后可只用中文。绝不出现自创译名。
3. **数学**：公式用 KaTeX 渲染；行内用 `$...$`，独立成行用 `$$...$$`。渐进记号必须用原文符号 Θ/Ο/Ω，不要写成 "theta"。
4. **不装懂**：任何"这里显然"都要展开。凡是书里直接跳过的中间步骤，本站要补上，并标 `data-kind="note"`。
5. **不注水**：不写励志话、不写「这很重要哦」。每句话要么给信息，要么给类比。
6. **原文引用**：整段引用原文必须原样（含排版符号），中文解读放在紧邻的独立块里。

## 七、设计令牌（`assets/theme.css`）

### 7.1 语义色

| 令牌 | 用途 |
|---|---|
| `--bg-0 / --bg-1 / --bg-2` | 页面底 / 卡片 / 内嵌块（代码、公式） |
| `--fg-0 / --fg-1 / --fg-2` | 主文本 / 次要文本 / 弱提示 |
| `--bd-0 / --bd-1` | 常规边框 / 强调边框 |
| `--c-source` | **原文**底色（区分于讲解） |
| `--c-note` | **讲解补充**底色 |
| `--c-ok / --c-warn / --c-err` | 正确 / 提示 / 错误 |

### 7.2 可视化专用色（色盲友好，灰阶也能区分）

| 令牌 | 语义 | 明色 |
|---|---|---|
| `--viz-idle` | 未处理 | 灰 |
| `--viz-compare` | 比较中 | 琥珀 |
| `--viz-active` | 当前操作 | 紫 |
| `--viz-move` | 搬移中 | 紫（比 active 亮一档，叠加交叉斜纹 + 文字标签） |
| `--viz-done` | 已确定 | 蓝 |
| `--viz-result` | 结果/路径 | 青 |
| `--viz-mark` | 已访问标记 | 深灰 |
| `--viz-violation` | 违反不变量 | 红 |

**禁止**只靠红/绿区分状态（色盲不可辨），必须同时用形状或纹理或文字标签。

**明度阶梯**（明色下由浅到深）：`idle < compare < move < result < done < active < mark < violation`。
灰阶下靠这层阶梯区分，色相只作第二重线索。**刻意不增加第 8 个色相** —— 色相越多，
整块色板在色盲与灰阶下的可分辨性越差；语义相近的状态（如 active 与 move）用同色相的不同明度。

### 7.3 字体（三种声音，各有分工）

**零依赖红线**：不能引 Google Fonts / CDN 字体，字体栈必须落在系统已装字体上
（本机有思源宋体 `Noto Serif SC`、思源黑体 `Source Han Sans CN`、Palatino、Georgia、Cascadia Code）。

| 令牌 | 用途 | 字体栈（拉丁在前、中文在后） |
|---|---|---|
| `--font-display` | 书的身份：书名、章节号、Part 编号、序号 | `Palatino Linotype` / `Songti SC` / `Noto Serif SC` |
| `--font-sans` | **界面与讲解**：导航、按钮、标签、小标题、表格头 | `Source Han Sans CN` / `PingFang SC` / `Microsoft YaHei` |
| `--font-serif` | **书页**：英文原文引述、书页感正文 | `Palatino Linotype` / `Georgia` / `Songti SC` |
| `--font-mono` | 代码、伪代码、数值 | `Cascadia Code` / `JetBrains Mono` / `Consolas` |

「**原文用衬线、讲解用无衬线**」是本项目的**核心视觉惯例**（红线 R3），别动它。

## 七·五、编辑部视觉语言（2026-09 改版，写新组件前必读）

整站方向是**教科书编辑部风**：这是一本要陪着读者读下去的书，不是产品官网。
新的组件必须遵守下面几条，否则会把已经统一的语言重新打散。

| 规则 | 说明 |
|---|---|
| 立体感来自发丝线与底色差 | **不用漂浮阴影**。圆角只有 `--radius-sm/md/lg` = 2/4/6px；`--radius-pill` 只留给状态胶囊 |
| 一个强调色走到底 | 明色 `--accent` 是墨蓝，暗色提亮到 AA。状态色（ok/warn/err）只做点缀且低饱和 |
| 不用纯黑 | 明色底色是暖纸白，文字是近黑墨字；暗色是炭墨底 + 暖白字 |
| 分组靠「一条线 + 留白」 | 优先 `border-bottom` 发丝线，不要给每块套框 |
| 进度用**离散刻度**，不用进度条 | 需要表达 n/m 时用 `.ticks`（每格一个 `<i>`，完成的加 `data-on="1"`）。**禁止**「有背景轨道的填充进度条」 |
| 编号是版式的一部分 | 章节号、Part 罗马数字、阶段号都用 `--font-display` 且 `font-variant-numeric: tabular-nums` |
| 「待建」是文字标签，不是圆点 | 真实语义状态可以有标记，但不用装饰性彩色小圆点 |
| 行内公式不折行 | `.katex-inline` 已设 `white-space: nowrap` |
| 中文正文 | 字号 `--fs-md`（17px）+ 行高 `--lh-read`（1.85）；英文原文 17px + 1.75 |
| 动效要有理由 | `MOTION_INTENSITY` 低：只用于状态变化与教学反馈，且必须包 `prefers-reduced-motion` |

**关于中文破折号**：站内中文讲解里的 `——`（破折号）是中文标点，保留。
「禁止 em-dash」那条规则针对的是**英文营销文案的设计套路**，不适用于中文技术写作原文。

**首页的信息架构**：首页 = 书的目录（报头 → 续读条 → Part 目录 → 附录 → 页脚），
其中进度层（`.ticks` / 已建与完成读数 / 当前章书签条）是刻意加的一层，

## 九、自动化闸门（写完关卡必须跑）

清单里「原文可溯源 / C 代码不漂移 / 链接有效 / 术语有出处」四项现在有机器检查，
不要再用肉眼对：

```bash
# 1) 从站点源码导出关卡数据（读真实关卡，不依赖任何手工副本）
node tools/dump_levels.mjs

# 2) 关卡合规：要求 0 ERROR
python tools/04_verify_level.py
```

它检查四件事：

| 检查 | 判据 | 为什么不能用「相似度」 |
|---|---|---|
| 英文引述可溯源 | 引述的字必须**一个不缺、按原序**出现在声明页 ±1 的窗口里；引述里写 `…` 表示省略，省略处两侧各自仍受此约束 | 相似度阈值放过一次，就等于允许改写原文 |
| 语料侧伪影 | 允许夹带（脚注整段、页间伪代码块、图注），但**每段** ≤ 800 字符 | 夹带是 PDF 抽取顺序造成的，不是引述的问题 |
| C 代码一致 | 关卡内嵌的 C 必须与 `c/*.c` 逐行相同 | 手工复制必然漂移 |
| 术语卡有出处 | 术语的每个英文词都要在声明页 ±1 的窗口里出现 | 术语是词表不是原句，不能整句比对 |

`WARN` 级：指向尚未构建章节的解锁预告链接——这是刻意的前向引导，不算失败。

**两条踩过坑、必须守住的实现约定：**

1. **页眉剥离正则必须形状严格，且全项目只有一套。** 曾用
   `^(?:\d+ )?(?:Chapter|Part|Appendix)\s+\d+.*$` 剥页眉，把正文整句
   `Chapter 4 presents the "master theorem," …` 也删了——引述比对从此永远失败，
   而现场看不出原因。现在 `03_segment.py` 与 `04_verify_level.py` 共用同一组
   `RUNHEAD_RES`，并由 `test_segment.py` 第 [5] 节钉住「六种页眉必须删、四类正文句必须留」。
2. **引述比对只需要一个入口，且必须用 `qnorm`。** 曾同时存在「折叠空白」与
   `qnorm` 两套归一化，术语卡走了弱的那套，于是 `random-access machine` 在语料
   `randomaccessma- chine` 上永远匹配不上。
